About the Service

Overview

Coder Workspaces are on-demand virtual machines with commonly used data science tools pre-installed. Anyone with a UCSB NetID can create a workspace to use for the duration of the academic quarter. Workspaces are deleted at the end of each quarter.

The service is managed by the Library DREAM Lab and uses computing resources provided by the College of Letters and Science IT (LSIT).

See our Getting Started Guide for a step-by-step introduction to creating and connecting to your first workspace.

Hardware and Software

Each workspace is an isolated virtual machine running Ubuntu Linux with dedicated resources:

Resources Description
CPU 4 vCPUs
Memory 16 GiB
User Data Disk 64 GB
OS Disk 15 GB

Default Software

All workspaces include the following software pre-installed:

Name Version Description
Ubuntu Linux 26.04 LTS Operating System
Docker 29.8.0 Container Runtime
Pixi v0.80.0 Python package manager
R v4.6.1 R programming language
Git v2.53.0 Version control software
gh v2.46.0 GitHub CLI
jq v1.8.1 Command line JSON processor
uv / uvx 0.12.13 Python package installer/runner

Additional software may be installed using apt or pixi.

Optional Software

Services can be enabled when the workspace is created on the New Workspace form:

Service Version Description
RStudio Server v2026.08.2 Run RStudio in the browser
VS Code Web — Run VS Code in the browser
VS Code Desktop (Server) — Connect to the workspace using local VS Code

Workspace Lifecycle

  • Workspaces shut down (stop) after four hours of inactivity.
  • You can manually stop a workspace by clicking the “Stop” button in Coder.
  • To start a stopped workspace, click the workspace’s “Start” button. It may take a couple of minutes to resume.
  • Deleting a workspace deletes all files on the workspace!
  • All workspaces will be deleted at the end of each academic quarter.

Policies

!
Backup Your Data

Data is not backed up; users are responsible for their own backups. Please use GitHub, Google Drive (via Rclone), or download important files regularly.

  • Backup your data: Data is not backed up; users are responsible for their own backups.
  • Deletion: All workspaces are automatically deleted at the end of each quarter.
  • Limits: Users may create and use only one workspace at a time. Multiple active workspaces may be deleted without notice.
  • Maintenance: Workspaces may be inaccessible during scheduled maintenance windows (announced via email).
  • Inactivity: Workspaces stop automatically after four hours of inactivity to conserve resources. They can be resumed by clicking the “Start” button.
  • Software Installation: Users may install additional software using standard package managers.
  • Access by Staff: Workspaces may be accessed by staff in the Library or LSIT. Confidential or sensitive information should not be stored.
